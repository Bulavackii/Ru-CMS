# 🐘 Обслуживание базы PostgreSQL

Скрипты для разовых операций с базой. Оба запускаются **под суперпользователем
`postgres`** — обычной роли приложения таких прав не дают намеренно.

| Скрипт | Когда нужен |
|:---|:---|
| [`rename-database.sql`](rename-database.sql) | у базы и роли осталось старое имя (`rucms_dev`), надо привести к тому, что в `.env` |
| [`create-database.sql`](create-database.sql) | базы нет вовсе, поднимаем с нуля |

```bash
"C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -h 127.0.0.1 -d postgres -f scripts/rename-database.sql
```

## 🪟 Windows: переименование одним скриптом

Если пароль суперпользователя утерян (а на этой машине он утерян — проверено:
`pgpass.conf` нет, pgAdmin ни разу не запускался, сохранённых реквизитов нигде
не осталось), есть готовый скрипт. Он временно разрешает локальный вход без
пароля, переименовывает роль и базу и **сам возвращает настройки обратно**.

```powershell
pwsh -ExecutionPolicy Bypass -File scripts/rename-database.ps1
```

Запускать в консоли **«от имени администратора»**, предварительно закрыв
`php artisan serve` и pgAdmin.

Что делает по шагам:

| Шаг | Действие |
|:--:|:---|
| 1 | Копирует `pg_hba.conf` рядом, с отметкой времени |
| 2 | Меняет `scram-sha-256` на `trust` в трёх строках (local, 127.0.0.1, ::1) |
| 3 | Перезапускает службу |
| 4 | `ALTER ROLE … RENAME`, `ALTER DATABASE … RENAME`, владение и права |
| 5 | **Возвращает `pg_hba.conf`** и перезапускает службу |
| 6 | Проверяет, что без пароля вход больше не проходит |

> 🛑 Пока действует `trust`, локальная база открыта **без пароля** любому
> пользователю этой машины. Окно — несколько секунд, и возврат стоит в блоке
> `finally`, то есть отработает даже если переименование упадёт с ошибкой. Но
> запускать всё равно стоит тогда, когда за компьютером больше никого нет.

> ❗ **Данные не теряются.** `ALTER DATABASE … RENAME` меняет только имя:
> таблицы, схема `public` и содержимое остаются на месте.

> ❗ **Пароль роли не теряется тоже.** В `pg_hba.conf` стоит `scram-sha-256`, а
> он переживает переименование — обнулялся бы только старый `md5`. Значит,
> `DB_PASSWORD` в `.env` менять не нужно, только `DB_DATABASE` и `DB_USERNAME`.

> ⚠️ Скрипт пишет `pg_hba.conf` **без BOM**. `Set-Content -Encoding UTF8` в
> Windows PowerShell 5.1 добавил бы его, а PostgreSQL с BOM в первой строке
> откажется стартовать — и сервер уже не поднимется, чтобы это исправить.

## ⚠️ Если хочется сделать вручную

В `pg_hba.conf` все способы входа — `scram-sha-256`, то есть **только по
паролю**. Без пароля суперпользователя переименовать базу или роль нельзя:
`ALTER DATABASE ... RENAME` требует права `CREATEDB`, `ALTER ROLE ... RENAME` —
`CREATEROLE`, а у роли приложения нет ни того, ни другого (проверено:
`rolsuper=нет, rolcreatedb=нет, rolcreaterole=нет`).

Стандартный способ восстановить доступ — временно разрешить локальный вход без
пароля. **Требует прав администратора Windows.**

> 🛑 На время этой процедуры локальная база открыта для любого пользователя
> машины без пароля. Делайте это, когда никого больше в системе нет, и
> обязательно верните `scram-sha-256` на место — это последний шаг, пропускать
> его нельзя.

1. Откройте от имени администратора файл:

   ```
   C:\Program Files\PostgreSQL\18\data\pg_hba.conf
   ```

2. Замените `scram-sha-256` на `trust` в двух строках — `local all all` и
   `host all all 127.0.0.1/32`. **Сохраните копию файла до правки.**

3. Перезагрузите настройки (тоже от администратора):

   ```
   net stop postgresql-x64-18 && net start postgresql-x64-18
   ```

4. Задайте новый пароль суперпользователю:

   ```
   "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -h 127.0.0.1 -d postgres -c "ALTER ROLE postgres PASSWORD 'новый_пароль';"
   ```

5. **Верните `scram-sha-256`** в `pg_hba.conf` и снова перезапустите службу.
   Проверьте, что без пароля вход больше не проходит.

После этого работают оба скрипта выше.

## Почему имя базы можно и не менять

Имя базы данных нигде не показывается: ни на сайте, ни в панели, ни в
документации. К товарному знаку оно отношения не имеет — это внутренняя
инфраструктура. Если возиться с восстановлением пароля не хочется, старое имя
базы ничему не мешает; на новых установках `install.sh` и так создаёт
`nexum_core`.
