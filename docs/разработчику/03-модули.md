## 📄 `module.json`

```json
{
    "name": "MyModule",
    "title": "Мой модуль",
    "description": "Что он делает",
    "version": "1.0.0",
    "priority": 50,
    "providers": ["Modules\\MyModule\\Providers\\MyModuleServiceProvider"]
}
```

| Поле | Смысл |
|:---|:---|
| `name` | Системное имя = имя папки |
| `title` | Подпись в панели |
| `priority` | Порядок загрузки: меньше — раньше |
| `providers` | Классы провайдеров |

> ⚠️ **Осторожно**
> **Обратные слэши в JSON экранируются как `\\`, а не `\\\\`.** У модуля
> Localization однажды стояло четыре: JSON декодировал их в две, `class_exists()`
> возвращал `false`, и провайдер молча не регистрировался.

## 🧬 Провайдер модуля

```php
namespace Modules\MyModule\Providers;

use Illuminate\Support\ServiceProvider;

class MyModuleServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        $this->loadViewsFrom(__DIR__ . '/../Views', 'MyModule');
        $this->loadRoutesFrom(__DIR__ . '/../Routes/web.php');
        $this->loadRoutesFrom(__DIR__ . '/../Routes/admin.php');

        // ⚠️ mergeConfigFrom обязателен, если у модуля есть свой конфиг:
        // без него значения из файла модуля недоступны, и код тихо
        // работает на умолчаниях. Так у Captcha не действовал флаг
        // включения, а у Localization — список стран.
        $this->mergeConfigFrom(__DIR__ . '/../Config/mymodule.php', 'mymodule');

        // Команды — только те, что зовёт человек. Всё, что зовёт
        // расписание, регистрируется в bootstrap/app.php.
        if ($this->app->runningInConsole()) {
            $this->commands([\Modules\MyModule\Console\Commands\MyCommand::class]);
        }
    }
}
```

## 🚦 Шаги подключения нового модуля

| Шаг | Что сделать |
|:--:|:---|
| 1 | Создать `modules/MyModule/` по [структуре](02-структура-проекта.md#анатомия-папки-модуля) |
| 2 | Написать `module.json` и провайдер |
| 3 | Миграции положить в **`database/migrations/`**, не в модуль |
| 4 | Зарегистрировать модуль в таблице: `php artisan modules:sync` |
| 5 | Включить в панели: **Модули → включить** |
| 6 | Если нужен раздел в меню — добавить в `AdminSections` (см. ниже) |
| 7 | Подписи и синонимы — в `resources/lang/{ru,en}/admin.php` |

## 🧭 Раздел в панели

Все разделы объявлены **в одном месте** — `app/Support/AdminSections.php`:

```php
self::link(
    'mymodule',                 // ключ: по нему берутся подпись и синонимы
    'admin.mymodule.index',     // маршрут
    'puzzle',                   // значок
    'admin.mymodule.*',         // маска активного состояния
    module: 'MyModule',         // модуль: раздел исчезнет при выключении
),
```

Из этого списка строятся: боковое меню, выдвижное меню телефона, крошка в шапке
и **глобальный поиск**. Подписи — `admin.sections.<ключ>`, синонимы для поиска —
`admin.section_keywords.<ключ>`.

> ⚠️ **Осторожно**
> **Раздел, не добавленный сюда, недостижим.** Страницы будут работать по прямому
> адресу, но их не будет ни в меню, ни в поиске. Так годами были потеряны
> «Комментарии», «Отзывы» и «Сообщения» — обнаружено при описи модулей для этой
> документации.

> ❗ **Важно**
> **Без перевода синонимов поиск разделов на другом языке слепнет:**
> «appearance» не найдёт «Themes».

## 🔍 Почему модуль не подхватился

| Симптом | Причина |
|:---|:---|
| Маршрутов нет вовсе | Модуль выключен в таблице `modules` либо не зарегистрирован (`modules:sync`) |
| Маршруты есть, вьюхи не находятся | Не вызван `loadViewsFrom()` или неверный неймспейс |
| Конфиг всегда в умолчаниях | Не вызван `mergeConfigFrom()` |
| Провайдер не выполняется | Экранирование в `module.json` (`\\`), опечатка в классе |
| Миграция не выполняется | Лежит внутри модуля — переложите в `database/migrations/` |
| Команда «не существует» в расписании | Зарегистрирована в провайдере модуля, а не в `bootstrap/app.php` |

Диагностика:

```bash
php artisan route:list --path=admin/mymodule
php artisan modules:sync
php artisan config:clear && php artisan view:clear
```

## 🧱 Legacy-модули

Жёсткий список в `ModuleServiceProvider::loadLegacyModules()` — грузится всегда,
даже до установки, потому что на них ссылается базовый лейаут:

```
Menu · News · Categories · Files · Notifications · Users
```

Новый модуль добавляйте сюда, **только если он нужен до установки**. Обычному
модулю здесь не место: он должен выключаться из панели.

## ⚠️ Правила, нарушение которых стоило времени

> ⚠️ **Осторожно**
> **Не дублируйте маршруты ядра.** У медиатеки были две одинаковые четвёрки
> маршрутов — в модуле и в `routes/web.php`. Отвечал зарегистрировавшийся
> последним, поэтому выключение модуля не убирало раздел, а переводило его на
> ДРУГОЙ код с другой проверкой типов файлов.

> ⚠️ **Осторожно**
> **Не регистрируйте провайдеры дважды.** `bootstrap/app.php` когда-то и
> `require`-ил `bootstrap/providers.php`, и передавал его же в `withProviders()`
> — `boot()` каждого провайдера выполнялся дважды вместе со всеми `Event::listen()`.

> ⚠️ **Осторожно**
> **Не обращайтесь к БД в `boot()` без `try/catch`.** Во время установки
> реквизиты могут вести в никуда, и 500 получал сам мастер установки.
