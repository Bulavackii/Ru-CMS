## 🏛️ Архитектура: HMVC поверх Laravel

Обычное приложение Laravel + слой модулей. Модуль — это самостоятельный кусок
системы со своими маршрутами, контроллерами, моделями и вьюхами, который можно
включить и выключить из панели.

```
        HTTP-запрос
             │
             ▼
    ┌─────────────────┐
    │  bootstrap/app  │  посредники, команды, расписание
    └────────┬────────┘
             ▼
    ┌─────────────────────────────────────────┐
    │      ModuleServiceProvider              │
    │  ┌───────────────────────────────────┐  │
    │  │ loadLegacyModules()               │  │ ← БЕЗУСЛОВНО: нужны до установки
    │  │   Menu, News, Categories, Files,  │  │
    │  │   Notifications, Users…           │  │
    │  ├───────────────────────────────────┤  │
    │  │ loadActiveModules()               │  │ ← по таблице `modules`
    │  │   маршруты, вьюхи, провайдеры     │  │
    │  └───────────────────────────────────┘  │
    └────────┬────────────────────────────────┘
             ▼
     маршрут → контроллер → модель/служба → вьюха
```

### Два круга загрузки

| Круг | Что грузится | Когда |
|:---|:---|:---|
| **Legacy** | Жёсткий список модулей, без которых не построится даже лейаут | Всегда, в начале `boot()` |
| **Активные** | Всё из таблицы `modules` со `active = true` | После проверки установки |

> ❗ **Важно**
> **Почему так.** Базовый лейаут и глобальные Blade-компоненты обращаются к
> неймспейсам `Menu::`, `Notifications::`, `Categories::` на каждой странице —
> в том числе до установки. Гейт «установлено ли» раньше закрывал загрузку всех
> модулей, и мастер установки падал.

## 🔌 Точки входа

| Файл | Ответственность |
|:---|:---|
| `bootstrap/app.php` | Посредники, команды уровня приложения, расписание, обработка ошибок |
| `bootstrap/providers.php` | Список провайдеров |
| `app/Providers/ModuleServiceProvider.php` | Загрузка модулей |
| `routes/web.php` | Маршруты ядра (сайт, панель, вход) |
| `routes/api.php` | API |
| `app/helpers.php` | Общие функции: шорткоды, время чтения, контраст, автономность |

> ⚠️ **Осторожно**
> **В файлах маршрутов только `require`, никогда `require_once`.** PHPUnit гоняет
> все тесты в одном процессе: первый бут «расходует» `require_once`, и все
> следующие экземпляры приложения молча остаются без маршрутов. То же случилось
> бы на Octane и RoadRunner.

## ⏰ Фон и расписание

| Задача | Когда | Что делает |
|:---|:---|:---|
| `orders:cancel-unpaid` | каждую минуту | Отменяет неоплаченные заказы, возвращает товар |
| Сборка карты сайта | ежедневно 03:00 | `App\Jobs\GenerateSitemap` |
| Чистка кеша | еженедельно | Служебная уборка |

> ❗ **Важно**
> **Команда, которую зовёт расписание, регистрируется в `bootstrap/app.php`
> через `->withCommands()`, а не в провайдере модуля.** Провайдеры модулей
> поднимаются только у активных модулей: выключение «Оплаты» в панели дало бы
> «command does not exist» в журнале расписания каждую минуту, а товар перестал
> бы возвращаться в продажу.

## 📨 События и слушатели

Основные события — вокруг заказа: `OrderCreated`, `OrderStatusChanged`.
Слушатели шлют письма и уведомления.

> ⚠️ **Осторожно**
> **Письма уходят через `after_response()`** (`app/helpers.php`) — уже после
> того, как ответ ушёл в браузер. Очередь по умолчанию `sync`, поэтому даже
> слушатель с `ShouldQueue` выполнялся бы прямо в запросе, и недоступный SMTP
> подвешивал бы страницу. У почты выставлен таймаут 5 секунд.
