## 🗄️ База

**Прод — PostgreSQL.** Это осознанный выбор владельца («опенсорсная БД»); в
мастере установки выбора нет. Конфигурации других драйверов в
`config/database.php` остались и безвредны, но **ничто в приложении не должно
опираться на MySQL-специфичный синтаксис**.

**Тесты — SQLite** (`phpunit.xml`), ради скорости. Отсюда главное следствие:

> ❗ **Важно**
> **Миграции обязаны быть драйвер-нейтральными.** Только Schema Builder, никакого
> сырого SQL. Пять миграций когда-то лезли в `information_schema` за индексами —
> это MySQL-специфика; на Postgres одна из них падала жёстко.

---

## 📐 Правила миграций

| Правило | Почему |
|:---|:---|
| **Все миграции — в `database/migrations/`** | Модульные не выполняются вовсе: `loadMigrationsFrom()` никто не зовёт |
| **Schema Builder, не сырой SQL** | Прод Postgres, тесты SQLite |
| **`Schema::hasColumn()` перед добавлением** | Миграция должна переживать повторный запуск |
| **`dropForeign(['колонка'])`, а не по имени** | SQLite не умеет удалять ключ по имени |
| **Явное заполнение новых колонок** | У части драйверов `default` не применяется к существующим строкам |

Пример:

```php
Schema::table('news', function (Blueprint $table) {
    if (! Schema::hasColumn('news', 'show_on_homepage')) {
        $table->boolean('show_on_homepage')->default(true)->after('published');
    }
});

DB::table('news')->whereNull('show_on_homepage')->update(['show_on_homepage' => true]);
```

## 🌱 Сидеры и мастер установки

Содержимое сайта после установки заводится **командами модулей**, которые
вызывает `InstallController::finish()`:

| Команда | Что заводит |
|:---|:---|
| `menu:seed-default` | Три меню: шапка, подвал, боковое |
| `payments:seed-default` | Шесть способов оплаты |
| `delivery:seed-default` | Шесть служб доставки |
| `pages:seed-default` | Страницы сайта |
| `slideshow:seed-default` | Баннеры |
| `forms:seed-default` | Тринадцать форм |
| `captcha:seed-default` | Сборки каптчи |
| `visual:seed-*` | Темы и фрагменты |
| `categories:seed-default` | Категории **и раскладка уже созданного** |
| `seo:seed-pages` | SEO-записи для всех материалов |
| `accessibility:seed-default` | Виджет спецвозможностей |
| `orders:seed-demo` | Демонстрационный заказ |

> ❗ **Важно**
> **Порядок несущий.** Категории — последними из содержимого: команда не только
> заводит набор, но и привязывает уже созданные материалы. SEO-записи — после
> всего: описывать раньше нечего. Демо-заказ — после товаров и способов оплаты.

> ⚠️ **Осторожно**
> **Материалы, вставленные запросом (`DB::table()->insert`), не поднимают события
> модели.** Мастер установки так и делает ради скорости — поэтому SEO-записи для
> них заводит отдельная команда.

> ❗ **Важно**
> **Правило проекта: всё, что добавляется в содержимое, дублируется в сидер.**
> Иначе чистая установка перестаёт совпадать с боевым сайтом. Сверка описана в
> [проверке установки](../проверка-установки.md).

## 🧠 Кеш

Драйвер на проде — `file`. **Он не поддерживает теги**, поэтому `Cache::tags()`
использовать нельзя без проверки (один раз это дало 500 на любом сохранении меню).

| Ключ | Срок | Что сбрасывает |
|:---|:---|:---|
| `home_pages` | 1 час | Правка/удаление `Page` |
| `home_menus`, `home_categories`, `home_slideshows` | 1 час | — |
| `menu.<позиция>` | 1 час | Правка меню, пункта **и страницы** |
| `template_<шаблон>_v<версия>_<хеш>` | 5 минут | Версия из `News::contentVersion()` |
| `admin_dashboard_stats` | 5 минут | — |

```bash
php artisan cache:clear      # разовая чистка
```

> ⚠️ **Осторожно**
> **Заводя кеш, перечислите ВСЕ модели, чьё изменение делает его неверным.**
> Пункт меню собирается из страницы — значит, правка страницы обязана сбрасывать
> кеш меню. Пока этого не было, удалённая страница висела в меню ещё час.

> ⚠️ **Осторожно**
> **`decrement()` и `increment()` не поднимают событие `saved`.** Только
> `updating` и `updated`. Списание товара при покупке идёт именно счётчиком —
> поэтому модель `News` подписана на `created` + `updated`, а не на `saved`.

> ⚠️ **Осторожно**
> **Слушатель модели, написанный стрелочной функцией, обрывает цепочку.**
> `Dispatcher` прекращает обход, как только слушатель вернул ровно `false`, а
> стрелочная функция возвращает результат выражения всегда. `Cache::forget()` при
> пустом кеше вернул `false` — и все слушатели дальше молча не выполнялись.
> **Пишите `function () { … }`.**

## 🔗 Ключевые связи

```
News ──┬── news_category ── Category
       ├── Slideshow (по news_id)
       ├── SeoPage (по URL)
       └── OrderItem.product_id

Page ──┬── MenuItem.linked_id   ← пункт меню на страницу
       └── Category

Order ─┬── OrderItem
       ├── PaymentMethod
       └── DeliveryMethod

File ──── Category (одна)
```

> ⚠️ **Осторожно**
> **Отсутствующая связь — это не только битая ссылка, но и лишний пункт.**
> Пункт меню на удалённую страницу оставался живым на вид и вёл в никуда.
> Фильтровать такие пункты нужно **в запросе**, а не в шаблоне — иначе призрак
> ляжет в кеш.

## 🧾 Полезные команды

```bash
php artisan migrate                      # накатить
php artisan migrate:status               # что применено
php artisan modules:sync                 # синхронизировать список модулей
php artisan orders:cancel-unpaid --dry-run   # проверить отмену без действий
php artisan menu:seed-default --reset    # пересоздать демо-меню
```

> 📌 **Заметка**
> В песочнице разработки `php artisan` может падать на «could not find driver»,
> если `.env` смотрит в недоступную базу. Обход:
> `APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan …`
