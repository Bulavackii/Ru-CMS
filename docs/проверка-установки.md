# Сквозная проверка установки: поставить мышью, снести, повторить

Сценарий для агента (и для человека). Задача — пройти мастер установки так,
как его проходит покупатель: браузером, кликая по кнопкам, — убедиться, что
финальный шаг отрабатывает без обрыва, затем снести установку и повторить.
Цикл повторяется, пока три прогона подряд не пройдут чисто.

> **Зачем это заведено.** Финал `/install/finish` дважды падал у владельца с
> `ERR_CONNECTION_RESET`: содержимое записано, а страница не приходит.
> Тестами такое не ловится — там нет ни настоящего сокета, ни сервера
> разработки. Ловится только живым прогоном в браузере.

---

## 0. Перед началом — прочитать

- **База только PostgreSQL.** В мастере нет выбора СУБД. Тесты гоняются на
  SQLite, но мастер — нет.
- **База одна, и роль не умеет создавать новые** (`rolcreatedb = false`).
  Значит цикл идёт по действующей базе: она стирается и наполняется заново.
- **Поэтому первым делом — выгрузка.** Без неё сносить нельзя:
  ```bash
  php scratchpad/dump.php   # см. «Приложение А»
  ```
  Проверить, что файл появился и весит правдоподобно (сейчас ~0,76 МБ).
- **Что теряется при сносе, а что нет.** Содержимое (страницы, новости, меню,
  темы, категории, способы оплаты и доставки) восстанавливают сидеры — это
  проверено сверкой «чистая установка против боевого сайта». Не
  восстанавливаются: учётная запись владельца с его паролем и двухфакторной
  привязкой, записи медиатеки о лично загруженных файлах (сами файлы на диске
  остаются), любые ручные правки меню и тем.

## 1. Снести установку

```bash
php artisan db:wipe                 # сносит все таблицы схемы public
rm -f storage/install.lock          # без этого middleware не пустит в мастер
rm -rf storage/framework/sessions/* # чужие флаги шагов не должны утечь в новый прогон
php artisan view:clear
php artisan config:clear
```

`.env` мастер перепишет сам на шаге базы данных, но перед первым циклом
сними с него чистую копию и возвращай её в начале каждого:

```bash
cp .env .env.pristine     # один раз
cp .env.pristine .env     # перед каждым циклом
```

**Проверка, что снос удался** — все три условия обязаны выполниться:

| Что | Как проверить | Ожидание |
|---|---|---|
| таблиц нет | `select count(*) from information_schema.tables where table_schema='public'` | `0` |
| замка нет | `ls storage/install.lock` | файла нет |
| мастер открыт | `GET /install` | код 200, а не 302 на `/login` |

## 2. Поднять сервер

```bash
php artisan serve --port=8100
```

**Именно `artisan serve`, а не `php -S`.** Встроенный сервер сам по себе
ошибку не воспроизводит: её создаёт сторож `ServeCommand`, который каждые
500 мс сверяет mtime `.env` и при изменении гасит серверный процесс
`$process->stop(5)` — вместе с запросом, который в этот момент выполняется.
Мастер пишет `.env` на шагах «База данных», «Почта» и «Лицензия», поэтому
проверять надо под тем же сторожем, под которым живёт владелец.

Порт 8000 не занимать — там рабочий сервер владельца.

Запомнить PID: гасить сервер потом **только по PID**, не по имени процесса
(`taskkill /F /IM php.exe` однажды уже погасил заодно рабочий сервер).

## 3. Пройти мастер мышью

Открыть `http://127.0.0.1:8100/install` и дальше действовать кликами, а не
запросами: смысл прогона именно в том, чтобы повторить путь покупателя.

| # | Шаг | Что сделать | Что обязано получиться |
|---|---|---|---|
| 1 | Приветствие | выбрать язык (карточка с флагом), нажать «Начать установку» | переход на «Требования», в сессии `install_locale` |
| 2 | Требования | посмотреть счёт проверок, нажать «Продолжить» | все строки зелёные; если красная — чинить окружение, а не мастер |
| 3 | База данных | вписать хост, порт, имя базы, пользователя, пароль; «Проверить и продолжить» | `.env` получил `DB_*`, миграции прогнаны, таблиц > 50 |
| 4 | Администратор | имя, почта, пароль | пользователь создан, `install_admin_id` в сессии |
| 5 | Почта | «Пропустить» (шаг необязательный) | переход на «Лицензию» без записи `MAIL_*` |
| 6 | Лицензия | «Я разработчик», если кнопка есть, иначе ключ формата `XXXXXXXX-…` | `install.completed.license` в сессии |
| 7 | **Финал** | ничего не нажимать, только ждать | **см. следующий раздел** |

### Что считается правильным поведением финала

1. Браузер уходит на `/install/finish`.
2. Под сервером разработки и при свежем `.env` показывается **страница
   ожидания** «Устанавливаем содержимое» с бегущей полосой. Это не
   украшение: она пропускает момент, когда сторож перезапускает сервер.
3. Страница сама возвращается на `/install/finish`, тот делает работу
   (два десятка сидеров), кладёт сводку в сессию, создаёт
   `storage/install.lock` и отдаёт **короткий редирект** на `/install/done`.
4. `/install/done` показывает итог: предупреждения (если были), применённую
   локализацию, рекомендации, отсчёт на главную страницу сайта.
5. Отсчёт досчитывает до нуля, подпись меняется на «Открываем главную
   страницу сайта…», браузер уходит на `/`.

**Ошибкой считается:** `ERR_CONNECTION_RESET`, белая страница, зависание
дольше 30 секунд, редирект на `/login` или в личный кабинет, счётчик,
замерший на «через 0 с».

## 4. Проверить результат

Не глазами по странице, а запросами. Минимальный набор:

```bash
php artisan tinker --execute="
  printf('таблиц: %d%s', \Illuminate\Support\Facades\DB::selectOne(
    \"select count(*) c from information_schema.tables where table_schema='public'\")->c, PHP_EOL);
  printf('страниц: %d, новостей: %d, меню: %d%s',
    \Modules\Menu\Models\Page::count(), \Modules\News\Models\News::count(),
    \Modules\Menu\Models\Menu::count(), PHP_EOL);
  printf('способов оплаты включено: %d, доставки: %d%s',
    \Modules\Payments\Models\PaymentMethod::where('active', true)->count(),
    \Modules\Delivery\Models\DeliveryMethod::where('active', true)->count(), PHP_EOL);
  printf('заказов: %d (обязан быть 0)%s', \Modules\Payments\Models\Order::count(), PHP_EOL);
"
```

Затем открыть браузером и убедиться, что живой сайт отвечает:

- `/` — главная со слайдером и карточками;
- `/admin` — панель под созданной учётной записью;
- в шапке сайта кнопка «Админка» видна (мы вошли администратором).

---

## 5. Снести и повторить

Вернуться к разделу 1. Цикл считается закрытым, когда **три прогона подряд**
прошли без единой ошибки из списка выше.

Между циклами обязательно:

- погасить сервер по PID и поднять заново (иначе следующий прогон стартует с
  прогретым кешем конфига и проверит не то);
- очистить сессии, иначе флаги пройденных шагов пустят мастер вперёд по
  прямому URL и часть пути окажется непроверенной.

## 6. Разбор частых поломок

### Что этот сценарий уже поймал (14.08.2026)

Первый же прогон мышью вскрыл то, чего не видел ни один тест: финал
переписывал `.env` **в самом начале** — `LICENSE_KEY` (тем же значением, что
уже записал предыдущий шаг) и ключи локали. Сторож гасил сервер посреди
двух десятков сидеров, и страница ожидания уходила в петлю. Починено
идемпотентностью `writeEnv()` и переносом записи в конец шага.

Три прогона подряд после починки, разными путями:

| Цикл | Путь | Перезапусков сервера | Итог |
|---|---|---|---|
| 2 | ключ лицензии, `.env` с ключами локали | 1 | `/install/done` → главная |
| 3 | «покупательский» `.env` без ключей локали | 2 | `/install/done` → главная |
| 4 | «Я разработчик» (записи в `.env` нет) | 0 | сразу редирект на `/install/done` |

Во всех трёх состав базы совпал: 62 таблицы, 10 страниц, 27 новостей,
7 меню, 11 категорий, 11 тем, 37 SEO-записей, 0 заказов, 1 администратор.

---

| Симптом | Причина | Что делать |
|---|---|---|
| `ERR_CONNECTION_RESET` на финале | сторож `artisan serve` погасил сервер после записи `.env` | смотреть, показалась ли страница ожидания; сверить mtime `.env` со временем старта процесса сервера |
| Страница без стилей | битая скомпилированная вьюха (на Windows `rename` в `storage/framework/views` иногда получает отказ) | `php artisan view:clear` |
| Любой адрес уводит на `/install` | нет `storage/install.lock` | так и задумано: пока замка нет, система считается неустановленной |
| `/install/*` уводит на `/login` | замок уже есть | это конец установки, а не ошибка; итог смотреть на `/install/done` |
| Финал отдал 500 | смотреть `storage/logs/laravel.log` | лог растёт быстро, читать хвост |
| Шаг «Почта» висит | недоступный SMTP | таймаут 5 с задан в `config/mail.php`; порт 465 у многих провайдеров закрыт, рабочий — 587 |

## Приложение А. Выгрузка и возврат базы

Выгрузка (пароль берётся из конфига приложения и нигде не печатается):

```php
$c = config('database.connections.pgsql');
$env = getenv() + ['PGPASSWORD' => (string) $c['password']];
proc_open(sprintf('"%s" -h %s -p %s -U %s -d %s --no-password -f "%s"',
    'C:\Program Files\PostgreSQL\18\bin\pg_dump.exe',
    $c['host'], $c['port'], $c['username'], $c['database'], $out), $desc, $pipes, $root, $env);
```

Возврат — тем же путём через `psql -f`. Перед возвратом обязательно
`php artisan db:wipe`, иначе выгрузка ляжет поверх существующих таблиц и
упрётся в конфликты ключей.

⚠️ Читать `.env` напрямую нельзя — это файл с секретами, и доступ к нему
закрыт. Реквизиты берутся только через `config()`.
